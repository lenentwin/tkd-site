## Состояния данных

«Мои тренировки» сообщает, что сервис расписания/истории ещё не подключён. Пустая история не выдаётся за подтверждённое отсутствие тренировок. «Мои данные» показывает только внутренний id и роль из проверенного профиля, не вымышленные ФИО. Аккаунт заявителя не отождествляется с учеником.

Форма имеет только React state. Она не вызывает BookingService, fetch, sendBeacon, Storage или IndexedDB. Кнопка «Проверить заполнение» выполняет только Zod-валидацию; сообщение явно говорит, что заявка не отправлялась. После ухода из раздела состояние удаляется. Никаких новых БД, аналитики или внешних обработчиков формы нет. Значения не записываются в URL/логи.

## Проверка существующего backend

Итог локального QA: lint/typecheck PASS, 25 unit-тестов PASS; 122 сценария кабинета на шести ширинах PASS, 0 pageerror, POST только logout; 39 проверок публичных/анонимных страниц PASS, 0 pageerror/POST, Hero/theme/CSP/артефакт PASS. Скриншоты desktop и smartphone в обеих темах просмотрены; на телефоне навигация показывает все четыре раздела без скрытых пунктов. Подключение на production использует созданные публичные Actions Variables VITE_AUTH_ENABLED=true и VITE_API_BASE_URL=https://api.mft39.ru. Действующие секреты не добавлялись.

Реальные анонимные обращения подтвердили health=200, me=401 с точным Allow-Origin=https://mft39.ru и Credentials=true, start=302 на oauth.yandex.ru с PKCE S256. Это **не подтверждение успешного OAuth-входа**.

Обнаружена особенность веб-сервера: OPTIONS /api/logout/ возвращает 405 до PHP, а OPTIONS /api/logout/index.php возвращает 204 с правильным CORS. Frontend использует прямой /api/logout/index.php; сервер нормализует его к тому же защищённому маршруту. Заголовок X-CSRF-Token, cookie и серверная схема авторизации сохранены. Настройки Cludex не исправлялись в обход ограничения задания.

Профили и успешный вход в браузерных тестах — явно синтетические fixtures, а не доказательство живого OAuth. Завершение настоящего входа владельцем через Яндекс и проверка собственного аккаунта остаются ручной приёмкой. Нужны уже настроенное Яндекс-приложение и действующие серверные сессии; секреты не запрашивались и не публиковались.

## Воспроизведение QA

Для production-проверки локально задайте VITE_AUTH_ENABLED=true и VITE_API_BASE_URL=https://api.mft39.ru только на время команды сборки, затем выполните npm run build и node scripts/prepare-pages.mjs. node scripts/qa-account.mjs поднимает собственный статический сервер и использует исключительно fixtures API. Для scripts/qa-release.mjs нужен npm run preview -- --port 4183. На другой системе BROWSER_PATH для qa-account указывает установленный Chromium/Edge. Скриншоты и результаты: test-results/account и test-results/release; они исключены из Git.
