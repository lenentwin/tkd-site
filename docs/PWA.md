# MFT39 как PWA

PWA дополняет существующий сайт React + TypeScript + Vite. Те же страницы, темы, маршруты, Яндекс ID и российский PHP API. Отдельного frontend, новой базы, push-сервиса, аналитики или платёжной интеграции нет.

## Установка

Android (Chrome): откройте https://mft39.ru, нажмите «Установить MFT39» внизу страницы и подтвердите предложение браузера. Если предложение не появилось: меню ⋮ → «Установить приложение» или «Добавить на главный экран».

iPhone/iPad: откройте https://mft39.ru в Safari → «Поделиться» → «На экран Домой» → «Добавить». Если показан переключатель «Открывать как веб-приложение», оставьте его включённым. Автоматического beforeinstallprompt на iOS не требуется: кнопка сайта показывает эту инструкцию. Установка и особенности современных web apps описаны [WebKit](https://webkit.org/blog/16993/news-from-wwdc25-web-technology-coming-this-fall-in-safari-26-beta/#every-site-can-be-a-web-app-on-ios-and-ipados).

Компьютер: Chrome/Edge → значок установки в адресной строке или меню установки приложения. Safari на Mac → «Файл» → «Добавить в Dock». Названия меню зависят от версии браузера; обычная вкладка остаётся полностью рабочей.

После установки запустите MFT39 по иконке. Может потребоваться войти через Яндекс заново: установленное приложение и обычная вкладка на некоторых платформах используют разные сеансы. Пароль вводится только у Яндекса. Ключи/сеансы через localStorage или URL не переносятся.

## Кэш и приватность

Manifest: public/manifest.webmanifest, id/start_url/scope=/, display=standalone, цвета существующей тёмной темы. Иконки: PNG192,512,maskable512,Apple180; экспортируются из существующего public/favicon.svg командой node scripts/generate-pwa-icons.mjs.

build/pwa.ts — собственный небольшой Vite-плагин без дополнительных npm-зависимостей. Он обрабатывает окончательный HTML с CSP, собирает список статических файлов, вычисляет SHA256 каждого файла и компилирует src/sw.ts стандартным Vite. SW-кэш версии определяется всем набором файлов. Неполная публикация с несовпадающей контрольной суммой не активируется как готовый офлайн-набор.

Кэшируются только публичные файлы из сборки: index.html без пользовательских данных, JS/CSS, шрифты, иконки и подготовленные публичные изображения. Заполнение CacheStorage происходит только при установке SW по списку сборки, credentials=omit. Произвольные runtime-ответы в кэш не добавляются.

Не кэшируются:
- PHP API на api.mft39.ru и любые внешние origins;
- /api, /auth, /oauth, /callback;
- ответы со сведениями об учениках, заявках, оплатах, профилях, CSRF и device tokens;
- POST/другие изменения, запросы с Authorization и URL с code/state/token/другими security-параметрами;
- HTML личных маршрутов, адреса с персональными query-параметрами, DEV-редактор и его runtime-содержимое.

Для OAuth/API worker выполняет обычный сетевой запрос с cache=no-store, сохраняя исходные cookies, CSRF и перенаправления. При недоступной сети результат — ошибка подключения, без поддельного успеха, фоновой очереди или автоматического повтора записи.

index.html — статическая CSR-оболочка. При офлайн-навигации она позволяет запустить Router; это не сохранённая страница кабинета. Кабинет сразу показывает отсутствие соединения и не показывает предыдущие персональные данные. После восстановления сети заново проверяется серверная сессия и загружаются актуальные сведения.

Публичные страницы без сети отмечаются сообщением о сохранённой версии. Яндекс ID, запись, ученики, оплаты, внешние карты и видео требуют сети. Первый визит и первоначальное сохранение ресурсов также требуют подключения. Черновики форм остаются только в памяти; уход из раздела, потеря сети с закрытием приватного экрана или перезагрузка очищают их. PWA не добавляет хранения ПД в browser storage.

## Обновление

Новую версию браузер скачивает в отдельный проверяемый статический кэш. Затем появляется уведомление «Доступна новая версия MFT39»: «Обновить» или «Позже». Страница сама не перезагружается во время работы. Перед обновлением завершите заполнение формы: нажатие «Обновить» явно перезагрузит текущую вкладку и очистит несохранённые поля.

Первый запуск не считается обновлением. Другие открытые вкладки не перезагружаются автоматически; для них сохраняются статические файлы двух предыдущих версий и предложение обновиться отдельно. Более старые кэши MFT39 удаляются при активации, чужие кэши не затрагиваются. Проверка обновлений идёт при возврате в приложение, восстановлении сети и раз в час при открытой видимой странице.

Регистрация: /sw.js, scope=/, updateViaCache=none. GitHub Pages не применяет public/_headers; обновление самого worker не полагается на этот файл. Для Cloudflare заголовки запрещают долгий кэш sw.js и заставляют перепроверять manifest. CSP разрешает только свои worker/manifest; unsafe-eval или внешние PWA-скрипты не добавляются.

## Сборка и проверка

Node24, существующий package-lock:

    npm ci
    npm run lint
    npm run typecheck
    npm test
    npm run build
    node scripts/prepare-pages.mjs
    npm run test:pwa

Для production-проверки кабинета VITE_AUTH_ENABLED=true и VITE_API_BASE_URL=https://api.mft39.ru задаются ДО сборки. Это публичные параметры, не секреты. Для браузерного теста нужен установленный Edge на Windows либо Chromium Playwright; BROWSER_PATH переопределяет путь.

Для Cloudflare обычная npm run build сохраняет нативный SPA fallback; prepare-pages.mjs нужен только GitHub Pages и добавляет404/CNAME. Он также проверяет, что SW ссылается на SHA256 окончательного HTML, включая CSP. В dev Service Worker не регистрируется, /editor и существующие инструменты разработки остаются на своём месте.

test:pwa запускает реальный SW/CacheStorage на локальном production-артефакте: manifest/icons, офлайн-public/private, запрет личного кэша, установка через browser event adapter, руководства платформ, OAuth-переходы с фиктивными ответами, явное обновление двух вкладок, сохранение чужого черновика, отклонение неполной версии и свежая авторизация после сети. Все account/OAuth-данные синтетические; это не приёмка настоящего Яндекс-аккаунта или физических телефонов.

Workflow проверяет ветки codex/** и PR без публикации; main дополнительно публикует dist. В CI устанавливается Chromium и выполняется test:pwa, поэтому регрессии приватности/обновлений блокируют деплой. Старые browser suites отдельно проверяют обычный сайт с serviceWorkers=block как обязательный fallback; PWA проверяет собственный suite с serviceWorkers=allow.

## Приёмка на физическом устройстве

Установить на Android и iPhone, открыть по иконке, войти через настоящий Яндекс и проверить возврат в кабинет, статус роли и выход. Выключить сеть: public-информация помечена сохранённой, приватные данные скрыты. Вернуть сеть: серверная сессия проверяется заново. Оставить незавершённую форму, дождаться следующей публикации, нажать «Позже», затем осознанно обновить. Эти действия не подменяются одной мобильной эмуляцией браузера.
