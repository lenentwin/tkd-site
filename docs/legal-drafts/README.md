# Юридические документы MFT39: статус подготовки

Все четыре текста имеют статус **ЧЕРНОВИК**. Пользователь 15.11.2026 подтвердил подготовку черновиков без включения обязательного принятия на действующем сайте. Утверждение руководством в проекте не зафиксировано. Никакой файл из этой папки не является утверждённой окончательной редакцией.

Источники: политика из предоставленного файла (14422 байта, 165 строк, прочитана целиком); три остальных текста из сообщения пользователя. Содержание сохранено, заменены только поля email на `tkdmft39@mail.ru`. Источник email: существующие `src/content/site.content.ts`, contacts.email. Это найденный адрес сайта; принадлежность и приём обращений по персональным данным должен подтвердить оператор. Подтверждение доставки писем не выполнялось.

`registry.json` управляет статусом и версией. `npm run legal:generate` формирует единый JSON для PHP и frontend. SHA-256 вычисляется от полного нормализованного текста UTF-8/LF. `npm run legal:check` проверяет соответствие исходникам, `npm run legal:release-check` дополнительно запрещает выпуск черновиков. Сборка чернового проекта разрешена, принятие чернового документа сервером запрещено.

До утверждения требуется согласовать:

- Фактического владельца сайта и оператора данных. В соглашении и политике пока написано «Предполагаемый». Реквизиты предоставлены пользователем; юридическая проверка актуальной выписки ЕГРЮЛ не проведена.
- Срок либо ясный критерий окончания действия каждого из двух согласий. Поля `[УТВЕРДИТЬ ...]` оставлены намеренно.
- Конкретные сроки/критерии хранения аккаунтов, заявок, карточек учеников, месячных оплат, архивов, подтверждений, журналов и резервных копий; порядок отзыва и ответственного за обращения. Архивирование в коде не удаляет данные. Существующее подтверждённое удаление карточки удаляет и связанные подтверждения представителя, но сохраняет минимальный обезличенный след аудита. Необходимо решить, соответствует ли такой жизненный цикл утверждённым обязанностям хранения. Автоматический срок не придуман.
- Фактические журналы Cludex/веб-сервера, ротацию и резервные копии. PHP не пишет тела заявок/согласий в публичные логи, но журналы инфраструктуры не исследованы. Отметка «оператор должен проверить» пока остаётся в политике.
- Размещение основной MySQL в России, перечень инфраструктурных обработчиков, договоры/поручения и реальные потоки. Публичный frontend обслуживает GitHub Pages, API отдельно. Это не доказывает отсутствие IP/технических данных у поставщиков frontend; сведения детей/ответы приватного API в PWA не кэшируются.
- Правовое основание минимальной обработки при самом OAuth до послевходового экрана: существующий код уже создаёт аккаунт Яндекс ID, получает имя и устанавливает серверную сессию. Новый экран появляется ПОСЛЕ этого, как запрошено пользователем. Нельзя утверждать, что до этого экрана данные вообще не обрабатываются. Состав/основание должны быть отражены в утверждённых текстах.
- Точный перечень данных/целей для тренеров и администраторов: тексты описывают преимущественно родителя, а подтверждение требуется и персоналу перед кабинетом. При необходимости утвердить отдельное основание обработки сотрудников.
- В форме новых записей собирается год рождения, возраст вычисляется как текущий год минус год рождения, без точной даты рождения. Старые записи могут содержать только снимок возраста; год автоматически не выдумывается. В год 18-летия код консервативно требует представителя. Уточнить формулировки о возрасте и совершеннолетии.
- Сайт позволяет запись себя/совершеннолетнего, тогда как раздел 3 соглашения посвящён детям. Согласовать применимость текста к взрослым участникам.
- Представитель указывает ФИО/телефон/статус родителя, но документально полномочия онлайн автоматически не проверяются. Установить реальную процедуру проверки. Не обещать автоматическую проверку.
- В заявке есть желаемая дата и свободный комментарий. Согласие ребёнка не перечисляет их явно; решить необходимую детализацию и запрет на медицинские/лишние данные. Текущая форма уже просит не вводить такие данные.
- Публикации изображений/отзывов не включены в новое согласие. Не считать это разрешением на фотографии, рекламу или распространение.
