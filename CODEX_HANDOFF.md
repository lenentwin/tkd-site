# Граница следующего серверного этапа

Текущий результат — frontend-прототип. Ни одна заглушка не считается существующим серверным API. Реальные OAuth, серверные сессии, база пользователей, обработка заявок и административная авторизация не реализованы и не входят в этот этап.

## Auth и пользователь

`src/types/services.ts` задаёт `AuthService` и `UserSession`; `src/services/demo.ts` содержит явный demo-адаптер. `src/app/providers/AuthProvider.tsx` связывает его с UI. Он хранит только флаг демо-входа, а не токен или реальный профиль. `LoginPage` вызывает signIn и открывает кабинет. Header/Hero/контакты выбирают `/login` или `/booking` по session. `AccountPage` и `BookingPage` защищены только демо-состоянием, а не реальными правами.

При подключении Yandex ID замените AuthService серверным адаптером, выполняйте OAuth code exchange и проверку state/PKCE на соответствующей доверенной стороне, держите секрет клиента вне фронтенда. Настоящий профиль должен приходить с серверного endpoint после проверки сессии; ожидаемую модель нужно расширить отдельно и согласовать. Пароли Яндекса приложению не нужны. Серверные cookie/CSRF/сроки сессий — часть будущей архитектуры, не скрытые возможности текущего кода.

## Запись

`BookingRequest`, `BookingResult`, `BookingStatus`, `BookingService` отделяют UI от источника данных. DemoBookingService ничего не отправляет и возвращает только `demo-only`, без ложного подтверждения. Имена и даты рождения в форме фиксированы вымышленными значениями; изменяемые зал и желаемая дата также не сохраняются как заявка.

Будущая система должна согласовать группы/реальный календарь, полномочия родителя/совершеннолетнего, согласия и сроки хранения, серверную валидацию, статусы обработки и защиту от повторов. Только после этого заменяются readOnly тестовые поля и подключается настоящий submit. Не использовать экспорт конфигурации или localStorage для детских/родительских анкет, дат рождения, телефонов заявителей или медицинских сведений.

## CMS и медиа

Источник начальной конфигурации — `src/content/site.content.ts`; общая схема version 1 — `src/types/content.ts`. ContentProvider управляет редактируемым снимком, undo/redo и локальным слоем. `editor/persistence/contentStorage.ts` — заменяемая точка чтения/сохранения. Будущий сервер должен возвращать ту же согласованную структуру, проверять схему и права на каждую мутацию; желательно добавить версию документа/конкурентное редактирование. История текущего прототипа ограничена 40 снимками и не переживает перезагрузку.

`editor/persistence/mediaStorage.ts` хранит бинарные Blob в IndexedDB; данные ссылаются на `idb:<key>`. `useMediaSource` создаёт и освобождает object URL. `transfer.ts` экспортирует/импортирует конфигурацию и при выборе владельца включает локальные изображения в JSON-пакет. Для production замените IDB адаптером upload/media storage и устойчивыми разрешёнными URL; права на медиа и согласия на изображения несовершеннолетних необходимо обеспечить до публикации. Текущие нейтральные заглушки не являются фото реальных людей.

Редактор `/editor` открыт локально без пароля. Это честно обозначенный demo-доступ; он не обеспечивает безопасность публичной CMS. Реальная административная аутентификация, роли, аудит, серверные проверки, ограничения загрузки и публикационный workflow — будущий этап.

## VK, карты, RuTube, контакты

- `ReviewsSource` — контракт будущего источника отзывов. Публичный UI показывает только вручную подтверждённые отзывы со ссылкой на оригинал. Текущий пустой manual adapter не является автоматической синхронизацией. Автообновление VK требует отдельно проверенного официального источника, серверного хранения токенов, кэширования, модерации и fallback на ручные данные. Не превращать любые записи сообщества в отзывы.
- `getMapLink` принимает только разрешённые официальные домены. `getYandexEmbed` переводит короткий токен предоставленной Яндекс-ссылки в официальный iframe `api-maps.yandex.ru/frame/v1/-/…`; координаты и ID организаций не выдумываются. `MapSection` лениво загружает настоящий интерактивный виджет, пересоздаёт его при выборе зала, сохраняет прямоугольник и доступные текст/ссылку при загрузке и ошибке. Все три адреса проверены в реальном Edge. Для новых залов используйте официальную короткую ссылку; неподдерживаемый формат оставит честный внешний переход. 2ГИС убран из публичного UI по уточнению владельца; старое поле сохранено для совместимости JSON версии1.
- `getRutubeEmbed` принимает конкретные URL видео с официальным 32-символьным ID, создаёт официальный `play/embed` URL. Видео выбирается вручную. При отсутствии реального ролика не заявлять проверенное воспроизведение.
- `getGmailLink`, `copyPhone` отделены от UI. Clipboard success показывается после успешного Promise; при запрете операция сообщает ошибку. Mobile использует обычный tel:.

## Публикация и SEO

Публикации не было, старый проект не изменялся. Vite SPA использует семантику и route metadata, но для полноценного SEO публичные страницы следует предварительно рендерить (например, статическая генерация с актуальной конфигурацией) либо перенести на SSR/SSG без изменения модели секций. Закрытые demo/editor страницы должны остаться noindex; перед публикацией публичных страниц пересмотрите текущий глобальный noindex, canonical/OG URL и растровую OG-обложку. SVG OG — пока локальное место под обложку, не гарантия совместимости социальных платформ.

Основные доказательства и ограничения — `TEST_REPORT.md`, `REQUIREMENTS_CHECKLIST.md`, отчёт субагента. Build/typecheck не заменяют художественного утверждения владельцем.
